# Security exceptions

Dated, written exceptions for dependency findings that are **not fixed** and
are being shipped anyway.

**There are none today.** This file exists empty because the release gate
reads it, and because an exceptions process invented under pressure at the
moment it is first needed is an exceptions process that waves things through.

## How this works

The two-speed model, as affirmed:

- **Secrets and lockfile failures block every push.** No severity threshold,
  no exceptions, no entry in this file. They are binary, near-zero false
  positive, and always actionable by whoever just pushed.
- **Dependency CVEs annotate on every push** at every severity, as a pull
  request comment. They do not block.
- **Dependency CVEs block at the release gate.** Each Critical and High is
  either fixed, or carries a row below.

The reason for two speeds rather than one hard per-push gate is specific and
worth keeping in view: a solo developer who hits an unfixable transitive
Critical mid-unit, with no triage path and no second reviewer, bypasses the
gate once — and after one bypass it is decoration rather than a control.

## What a row must carry

| Field | Why |
|---|---|
| **Advisory** | The GHSA or CVE id, so the row can be re-checked |
| **Package and version** | The exact resolved version, from the lockfile |
| **Severity** | As the scanner reports it |
| **Reachability** | **The load-bearing field.** A High in a test-only or build-only dependency is not the same risk as one in the request path. Say which, and say how you determined it |
| **Why not fixed** | No patched version, a breaking upgrade, an upstream that has not responded |
| **Expires** | A date. An expired exception **fails the release gate** |
| **Accepted by** | Who decided |
| **Accepted on** | When |

## Expiry is not a formality

An exception with no expiry is a permanent silence. The gate fails on an
expired row rather than warning, so the choice at that point is to re-accept
deliberately or to fix the finding — both of which are decisions, which is
the point.

Default expiry is **90 days**. Shorter for anything reachable from a request
path carrying children's data [RC-1, RC-2, RC-3].
