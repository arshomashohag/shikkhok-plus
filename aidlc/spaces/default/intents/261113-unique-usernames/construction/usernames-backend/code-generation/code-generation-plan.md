# Code Generation Plan — usernames-backend (U1)

## Summary

- Builds: usernames end to end on the backend: sign-up with a username and the verify race, one-field sign-in with its own failure counters, both availability lookups, first choice, rename, reclaim, holds, the deletion hold, the username privacy gate.
- Touches: migrations/versions/0035_*, app/db/models.py, app/accounts/ (new usernames.py; service.py, passwords.py), app/auth/ (otp.py, pending.py, ceilings.py, hashing.py), app/api/ (auth.py, accounts.py, me.py), app/schemas/, app/contract/, app/governance/, app/audit/log.py, deploy/README.md, message-keys.json, openapi.json, docs/legal/PRIVACY.md, Makefile.
- Tests: about 80 pytest tests in 8 new or extended files, unit and integration against PostgreSQL 16 as the restricted role; every `test_first: true` rule written first.

## Inputs

Authoritative design, by path (the plan does not restate it):

- Functional design: `construction/usernames-backend/functional-design/` — `rules.md` (BR1.1–BR10.3), `entities.md`, `functional-spec.md` (§ 1 grounding and call sites, W1–W10 and W8a, § 3 state machines, § 6 error catalogue, § 7 concurrency, § 8 schema, § 9 review points).
- NFR requirements: `construction/usernames-backend/nfr-requirements/` — `security-requirements.md` (NFR1.x anti-enumeration, NFR2.x the twelve ceiling scopes in four families, NFR3.x privacy, and **§ Amendments to the functional design, which this plan implements in amended form**), `reliability-requirements.md`, `performance-requirements.md`, `scalability-requirements.md`, `observability-requirements.md`, `tech-stack-decisions.md` (no new dependency).
- Contracts: `inception/contract-design/contract-summary.md` C1 and C3 as amended by the NFRs (both lookups are `POST` with a body; `SignupRequest.username` required; no per-draft replacement counter or `retry_limit` key; `account.username.password_required` added; `username_reclaimed_at` added). Older installed app versions are not a compatibility constraint.
- U2 is built on this branch: reuse `app/db/advisory.py` (add the `username` namespace last in the lock order), `app/db/retry.py` (rename runs as one re-runnable unit of work, BR10.3), the non-committing consume where a count must roll back with its change, and leave the matcher call in `create_account_rows` and its lock line untouched (C3).

**One decision this plan adds**, settling the open Major in the NFR review: in Family D the cross-network peek refuses a network only when `un_fail_hour` ≥ 20 **and** this network's `un_fail_net_hour` ≥ 3 (not ≥ 1), so an owner who mistypes once or twice on their own network is not locked out after a stranger fills the cross-network counter. The per-account guessing bound in NFR2.5 becomes "20 before `un_fail_hour` fills, then at most 3 from each network that has not yet failed that name 3 times"; the test in Step 6 asserts the recomputed figure, and `security-requirements.md` NFR2.4/NFR2.5 are updated in the same change.
