  Not Met when its named verifier ran green in this run. Each gap is flagged

- **Open**: reopen U3 Code Generation for the flaky test, or accept it. This is

## Follow-up after the run: the timing-sensitive Android test

`UsernameGateRoutingTest` failed once under load. Its waits use 5 s of real time, while the account reads they wait for run on a real background thread. The orchestrator raised that test's real-time bound to 20 s and added a comment in the test explaining why.

**Why this does not weaken the test**:
- A wait ends as soon as its condition holds, so a passing run is no slower.
- Every assertion is unchanged.
- Only a failing run now waits longer.

**Why not the virtual-clock alternative**: it would mean injecting a test dispatcher into the session and its HTTP engine. That is a larger change to production wiring for a test-timing concern.

**After the change**:
- The test ran three times with `--rerun-tasks`, 7/7 each time.
- `detekt` and `testDebugUnitTest` are green.
- CI's `android-unit` job is the final check.
