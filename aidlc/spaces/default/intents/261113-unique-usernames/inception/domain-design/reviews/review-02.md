> R-01 Reviewer note: ADR-012 exempts a reclaim from the rename limit, leaves username_changed_at untouched and holds the name given up; the AccountDirectory behaviour text agrees. One residual gap is recorded under New findings.

> R-02 Reviewer note: ADR-005 states the match-time rule (an email links only records that record no phone) and lists the cross-account case as a test-first item; ContactMatching, StudentRoster and CentreMembership all repeat it consistently.

> R-03 Reviewer note: ADR-011 makes the refusal roll back (code unconsumed, draft intact), names the replacement-username field, the authorization (a live correct code) and a cap of 3. The cap itself cannot work as written; see New findings.

> R-04 Reviewer note: The upsert rule (latest release wins), the set-null foreign key on releasing_account_id and the migration order are now stated in ADR-002 and the UsernameHold entity.

> R-05 Reviewer note: The key is named (SHIKKHOKPLUS_OTP_HMAC_KEY, which exists in app/auth/hashing.py), the purpose prefix username-hold:v1: is fixed, and the rotation runbook line is recorded.

> R-06 Reviewer note: Six scope names are listed with lengths and I recomputed each (16, 12, 13, 15, 15, 15); the scope_value shape is u: plus 62 hex characters. The code confirms scope_kind is String(16) and scope_value is String(64).

> R-07 Reviewer note: ADR-007 records the amendment to FR3.1 and FR1.6 and says the owner sees the name they released as available to reclaim.

> R-08 Reviewer note: PrivacyGate and ADR-010 name MeResponse.username and the rename response's username as the two OWN_ACCOUNT_FIELDS pairs, and name FORBIDDEN_TOKENS as the admin list; the pair-tuple shape matches app/contract/privacy.py.
