# Architecture and engineering-quality review — 2026-11-11

**Reviewer:** architect agent · **Scope:** backend (`app/`, `migrations/`, `tests/`), the Android
and web contract linkage, CI (`.github/workflows/`), infra cron and monitoring · **Mode:** analysis
only. No source file was changed.

**How it was verified:** every claim cites `file:line`. Two claims were also checked against a
running system: `alembic upgrade head` applied to a throwaway PostgreSQL 16 container, followed by
`pg_indexes` and `alembic check`; and `openapi.json` was parsed to count operations and list
collection endpoints.

## Summary

The codebase has closed almost all of the 2026-10-22 gap list. Lockfiles with hash checks, CVE
scanning at both speeds, the Android quality toolchain, the `app.authz` strict island, the
asserted `PUBLIC_ROUTES` count, the "suite actually ran" assertion and the `ErrorEnvelope`
declarations all exist and do their job. The money boundary holds: the only `float(` calls outside
`app/money` are the JWT `exp` comparisons at `app/auth/tokens.py:346,410`, and no file outside
`app/money` imports `decimal`. Indexing on the list paths is thorough. Background jobs are
idempotent through constraints, scheduled, and covered by a heartbeat gate. Android and web are both
tested against `openapi.json` (`ContractConformanceTest.kt`, `web/scripts/check-generated.mjs`).

The material findings are structural rather than stylistic:

1. **The ORM metadata no longer describes the database.** `alembic check` fails. An
   autogenerated migration would drop two tables, two columns, about 20 indexes and one foreign
   key (ARC-1).
2. **Transaction ownership is stated one way and built another.** The documented rule is that the
   endpoint commits. In practice 116 `commit()` calls sit in service and API modules, which
   undercuts the middleware's guarantee that it rolls back on any 4xx or 5xx (ARC-2).
3. **A complete second money-decision path has no production caller and is still tested as if it
   were live** (ARC-3).
4. **The Bangla layout verifier was chosen and has never been run.** None of its 51 rows has been
   checked (ARC-4).
5. **Collection endpoints are unbounded by default**, and one of them is N+1 (ARC-5, ARC-6).

## Top 5 recommendations, ranked

**1. Restore ORM and migration parity, and gate it (ARC-1, with ARC-10).**
Why first: a routine `alembic revision --autogenerate` in a solo build would produce a migration that
drops `pending_signup` and two refresh-token columns used for token revocation. The person reviewing
it is the same person who generated it. Effort M.
Acceptance criteria:
- `alembic check` against a database at head exits 0.
- A test in the integration suite runs `alembic check`, or `compare_metadata`, against the testcontainer at head and fails on any difference.
- Any deliberate exclusion goes through `include_object` with a comment naming the reason.
- A fixture proves the gate fires: a model column with no migration makes it fail.

**2. Make transaction ownership one rule, enforced mechanically (ARC-2).**
Why: the middleware's rollback guarantee is the stated protection against partial money writes, and
116 service commits bypass it without anyone saying so. Effort L.
Acceptance criteria:
- The docstrings at `app/db/session.py:3-5` and `app/main.py:8-15` describe the rule as built.
- An AST gate fails if `.commit()` appears in any `app/` module outside an explicit allowlist. Each allowlist entry carries a reason, e.g. "must survive refusal: OTP attempt".
- IntegrityError handling uses `begin_nested()`.
- A test shows a handler that raises after its service write leaves no row behind.

**3. Delete the dead `verify_claim`/`reject_claim` path and re-point its tests (ARC-3).**
Why: the race tests give the fees surface confidence that comes from code production never runs.
Effort M.
Acceptance criteria:
- Neither name exists in `app/`.
- Every former test call goes through `approve_submission`/`reject_submission`, or through a fixture built on them.
- `tests/fees/test_decision_races.py` covers a double approve and an approve racing a reject on the live path.
- Backend coverage stays at or above 80% and `app.money` stays at 100% branch coverage.

**4. Give the Bangla layout obligation a verifier that has actually run (ARC-4).**
Why: it is the only affirmed ALWAYS rule with no executed check across six shipped units. Effort M.
Acceptance criteria, one of:
- (a) Every row in `bangla-layout-check.md` carries a date, a device and pass or fail, with failures fixed or ticketed; or
- (b) a Roborazzi or Paparazzi suite renders at least the D3 and D5 money screens and the sign-up screens at the longest Bangla string, runs in the `android-unit` job, and the document records which rows it replaces.

If (b) is chosen, the document states plainly that the remaining rows have no automated verifier.

**5. Bound the collection endpoints and fix the exam N+1 (ARC-5, ARC-6).**
Why: these grow with each term of use, and on a 2-worker, 2 GB host the cost lands as mid-class
latency (PU-3.6). Effort M.
Acceptance criteria:
- `/batches/{id}/sessions` and the announcement list default to a date window or cap, newest first, with keyset paging.
- `/v1/students` applies a default cap.
- A contract test lists every array-returning GET as capped or bounded by construction, and fails when a new unlisted endpoint appears.
- `GET /v1/batches/{id}/exams` runs in a constant number of queries, independent of exam count, asserted by a query-count test.

and ARC-13 (SBOM and Dependabot). Each is an S change and together they fit in one Bolt.
