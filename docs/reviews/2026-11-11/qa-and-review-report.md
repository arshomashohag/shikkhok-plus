  35 px to 170 px, the name went from 6 lines to 2, and the row height went

  Measured in Chromium with a Playwright probe.
- **ARC-1, schema drift:**
  - **Found by `alembic check`:** 2 missing tables, 2 missing columns,
    1 missing foreign key and 20 missing indexes. A `remove_index` for
    each index means an autogenerated migration would have dropped it.
  - **Found by the new catalogue comparison** (Alembic cannot see these):
    12 missing CHECK constraints and 7 foreign keys with misnamed

  - **Result:** all of it is resolved in the models, with no migration.
    `tests/db/test_schema_parity.py` now fails CI on any drift, and it is
    shown to fail on planted drift of each kind.

## 2. Process

1. **Analysis.** Four specialists (product, security, UX, architecture)
   reviewed the code independently. Their reports are in this folder.
2. **Planning.** The delivery manager merged them into `sprint-plan.md`:
   five streams, plus deferrals and decisions, each with a reason.
3. **Development.** Five developers worked in parallel, each in an isolated
   git worktree.
4. **Merge.** Each stream was merged only after checking its merge base.
   Generated files were regenerated after each merge, never hand-merged.
5. **Review.** Two independent reviewers read the merged diff without the
   developers' reports: one for the backend, one for web and Android.
6. **Fix rounds.** One for the backend (8 findings) and one for the clients
   (10 findings). Every new test was shown to fail without its fix.
7. **Verification.** The full `make check` ran on the final tree (section 4).

### Incidents and how they were caught

- **Stale worktree base.** The worktrees were created from a stale
  `origin/main` (PR #60), 17 PRs behind the sprint base. The first merge
  attempt conflicted. The merge was aborted and every stream was moved
  onto `6bf4dfa` before anything landed. Every later merge checked its
  merge base first.
- **Incomplete control (SEC-6).** The deletion route recorded dead codes
  but never refused on them, and its test checked only the counter. The
  backend reviewer caught it. A new endpoint test exercises the refusal.
- **Missed pinned test.** The Android `display_name` removal broke a
  type-level pin test, because only the sign-up tests had been run. The
  full `make check` caught it.

## 5. Known limitations, carried forward

- **No push for class changes.** Families get an inbox item only, because
  the product has no device-token store yet. FCM push is a separate
  decision.
- **Past classes stay editable.** A teacher can still cancel or move a
  past session, as before. Doing so sends no notification.
- **Android `displayTime` in other screens.** It still throws on a
  malformed server time in `GuardianHomeScreen`, `StudentParts` and
  `ClassPickList`.
- **"Leave batch" on Student detail** does not name its batch in its
  accessible name.
- **Clients do not know the 1000 exam cap.** They show the server's
  validation error instead.
- **CHECK constraint names.** Deployed CHECK constraints carry a doubled
  prefix (`ck_room_ck_room_name`). The models reproduce this exactly.
  Renaming them needs a migration.
- **Upgrading apps.** An old Android install's "mark all read" leaves
  class-change items unread until the app is upgraded. This is deliberate
  and documented in `mark_read`.
